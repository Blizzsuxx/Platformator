# Native GUI audit — 2026-11-05

Reviewed commit `b45bdff9` (`gui`), primarily `editor/`, against the Python implementation in `ui/` and selected Unity authoring workflows. The working tree was clean before this report. This is a source review plus native automated checks, not a human desktop usability session. Performance findings identify executed work and scaling risks; no CPU percentages, GPU timings, or speedup estimates were measured.

The native editor has a useful foundation: scene round-tripping, unknown-data preservation, targeted undo history, dockable panels, typed behavior metadata, separate build/run processes, cancellation, bounded process output, asynchronous directory scans, and visible asset tiles. Its main weaknesses are incomplete Scene authoring coverage, missing workflow conveniences, and avoidable work while the editor is idle or browsing assets.

## Platform support and distribution

**Windows and macOS are unsupported, explicitly.** Root `CMakeLists.txt:196` rejects every editor build whose system name is not Linux. The remaining work is substantive:

- `editor/CMakeLists.txt` always compiles `process_posix.cpp`. Its spawn, pipe, signal, process-group, and wait APIs need a Windows implementation with equivalent owned-process-tree cleanup, cancellation, nonblocking output, and argument handling.
- `documentio.cpp` directly uses `openat`, `linkat`, `renameat`, `fsync`, POSIX modes, and Linux `stat.st_mtim/st_ctim`. Preferences reuse this atomic writer. Implement platform file identity and atomic create/replace semantics; macOS also needs adaptation of these timestamp fields.
- Validate Windows Unicode paths and `.exe` defaults, executable discovery, dependency DLL deployment, CMake generators/configurations, and native dialogs. SDL dialogs already provide a useful abstraction; they are not the primary blocker.
- There is no editor install target in the root installation block. The default layout is read using a compiled source-tree resource path (`editor/CMakeLists.txt:68`, `editorapp.cpp:50`). A distributable application needs installed or embedded resources, runtime dependencies, and platform smoke checks.

**Detached panel windows are also absent.** Docking within the main window is enabled, but ImGui platform viewports are not enabled or integrated. This is a separate feature from Windows OS support. Python's `QDockWidget` workflow supports floating docks; the native README explicitly defers detached windows.

## Friendliness and useful Unity workflows

The interface is usable for a developer who understands the project, but it still exposes build plumbing and hides frequent authoring operations. The next improvements should reduce the number of times a user has to search menus, edit JSON, or understand internal protocols.

1. **Search and keyboard operation.** Add Hierarchy and Project search, searchable Add Component/Add Behavior menus, object-reference filtering, F2 rename, Delete, Ctrl+D duplicate, and an action/shortcut reference. Current Hierarchy mutations live in context menus. Keyboard navigation is not enabled via `ImGuiConfigFlags_NavEnableKeyboard`; review custom drawn rows/buttons for focus and activation as part of enabling it. Avoid relying on icon color alone for transform handles.
2. **Hierarchy organization and bulk editing.** Add undoable drag-to-reparent, sibling reordering, multi-selection, and multi-object transforms/properties. Reordering also matters because sprite draw order follows document order. Add editor-only hide/lock controls so a background can be excluded from selection without changing its runtime Active property. Unity documents [Hierarchy reordering and visibility/pickability](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference/hierarchy-window/hierarchy) and [multi-object Inspector editing](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-windows-views-reference/using-the-inspector/inspector-items).
3. **Precise placement.** Expose move/rotate/scale modes, local/world axes where meaningful, configurable position/angle/scale increments, and a simple rectangle tool for sprite/collider sizing. Unity's [grid and incremental snapping](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/scenes-manage-gameobjects/grid-snapping) is a useful model. Label rotation units; the current Inspector shows raw radians while the gizmo visually represents an angle.
4. **Actionable diagnostics.** Validation rows should select the offending object/component and focus its field. Console needs selectable text, Clear, auto-follow, filtering, and clickable compiler file/line locations. It currently shows only the final 64 KiB of a bounded 1 MiB log, without explaining that display cutoff or offering the retained earlier text. Unity's [Console search, filters, collapsed repeats, and clickable locations](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-windows-views-reference/console-window/console) are directly useful here.
5. **Guided project/run setup.** Discover presets and targets, browse for executables, offer a welcome/open-project flow when launch lacks a valid project, and replace the exposed `common-runner-v1` choice with clear status plus an advanced integration option. Show the active scene/project and save/run state consistently. Add an in-app UI scale control; scaling currently requires CLI/preferences. Review fixed-size tiles/icons/spacing at 100%, 150%, and 200% on real monitors.
6. **Safe reusable authoring.** Add component reset/copy/paste and subtree templates before a large prefab system. Duplication currently preserves all numeric references to their original targets, including references within the duplicated subtree; this is documented compatibility behavior, but can surprise someone duplicating a self-contained enemy assembly. Offer an explicit internal-reference-remapping option. Unity's [prefab model](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-gameobjects/prefabs) is a longer-term direction.
7. **Later workflow expansion.** Scene tabs, a Game view, pause/step, live inspection, and animation/sprite-sheet authoring would be useful. Embedded play/live inspection require lifecycle/process communication work because the current Scene preview deliberately does not run scripts or physics. These are larger projects than the preceding usability fixes.

The native editor already offers image tiles and animated asset thumbnails, so a recommendation to add all asset preview functionality from scratch would be inaccurate. Likewise, it already has undo/redo, project switching, drag/drop asset assignment, typed scene references, docking, and build cancellation.

## Additional avoidable performance work

| Area | Confirmed work | Recommended change |
| --- | --- | --- |
| Hierarchy | `visible_rows()` refreshes every row label on every draw (`hierarchy.cpp:91`, `:231`). `draw()` allocates two row-sized vectors and traverses all expanded rows several times to generate connector lines before the `ImGuiListClipper` (`:313`). Clipping saves widget submission but not these passes. | Refresh labels by value revision/changed IDs; cache topology and child ranges; draw only connector segments intersecting the visible rows. |
| Inspector asset fields | Each drawn reference calls `inspect_asset_reference`, including canonicalization and file existence checks (`referencefields.cpp:354`, `:479`). Idle selected objects repeatedly perform the same synchronous filesystem queries. | Cache display validity by project/path/type and asset-watch generation. Revalidate authoritatively on assignment/save/run. |
| Run Settings persistence | Each text/numeric change mutates preferences (`runsettings.cpp:14`); the app immediately persists (`editorapp.cpp:1806`). Persistence writes last-workspace, settings, and layout; atomic writes flush file/directory state (`documentio.cpp:203`). | Debounce or commit on field deactivation; write only changed preference data. Keep explicit document saves durable. |
| Asset changes | A recursive asset scan runs every three seconds. Any identity change clears browser thumbnails and calls `refresh_assets`, releasing and rebuilding every preview proxy (`editorapp.cpp:1405`, `preview.cpp:341`). A change to one unrelated file can reload the entire scene's assets. | Publish changed paths and invalidate dependent resources only; consider an OS watcher with bounded reconciliation scans. Do not rebuild the Scene on unrelated asset changes. |
| Source tracking | A recursive source metadata scan runs every five seconds even while idle (`editorapp.cpp:517`, `:1389`). It is asynchronous and bounded, which protects responsiveness, but still performs periodic filesystem work. | Use change notifications or a coarser idle interval; retain an explicit freshness check before building/running. |
| Preview cache | Each sprite proxy stores and compares `cachedObject = objectData`, including that object's entire children subtree (`preview.cpp:397`, `:540`). A deep chain with sprites on ancestors duplicates descendant JSON across proxies; worst-case storage is quadratic in chain length. Every changed object's descendants are visited even if only a non-transform field changed (`:277`). | Cache only local render/collider inputs; carry property categories in notifications so transform propagation and metadata-only edits take different paths. |
| Scene submission | Every visible Scene frame linearly submits all eligible sprites and generates all sprite/collider outlines, even for offscreen objects (`preview.cpp:647`, `viewport.cpp:760`). | First avoid unchanged-frame rendering. Then measure a focused offscreen workload before adding editor-specific culling; preserve document draw order and picking semantics. |

Positive performance choices worth retaining: idle `EditorPreview::reconcile` returns immediately when there are no changes, history retains affected data rather than full-scene snapshots, preview textures are reused when size is stable, asset tiles are virtualized, and scan/output limits exist. This is not a whole-document-serialization-every-frame implementation.

## Asset file-change detection and filesystem notifications

### Current behavior and findings

The ordinary new-asset path is wired: `editorapp.cpp:521` schedules an asynchronous recursive asset scan, normally three seconds after the previous result. `project.cpp:78` builds an identity from relative paths, file sizes, modification times, and subdirectory modification times. A new ordinary file changes that identity even if its size and timestamp match another file. After a detected change, `editorapp.cpp:1404` invalidates the browser and preview; visible browser directories then request fresh listings. Expected discovery latency is roughly the polling interval plus scan and UI scheduling time. This was established by source inspection; an interactive add-file test was not performed.

| Priority | Finding | Evidence and consequence |
| --- | --- | --- |
| Medium (historical finding; addressed) | Whole-tree polling and whole-preview invalidation | The baseline path called `ProjectPanel::refresh()` and `EditorPreview::refresh_assets()` for every detected identity change. Current watcher commits invalidate the affected Project/resource paths, and Scene preview refresh is limited to registered consumers; manual Refresh Assets retries failed referenced resources. The broad `EditorPreview::refresh_assets()` API and its whole-preview fallback have been removed. |
| Medium | Truncated scans suppress automatic refresh entirely | The watcher allows 50,000 files and 100,000 entries. `editorapp.cpp:1411` handles truncation as a warning and skips comparison/invalidation, so even a change in an already-visible small folder may never appear automatically while the tree remains above the bound. Keep visible-folder refresh usable when global coverage is incomplete. |
| Medium | Possible initial-baseline race | The first successful identity is adopted without invalidating browser listings (`editorapp.cpp:1420`). If a browser listing finishes before a file is added, but the initial watcher snapshot includes that addition, the listing can remain stale until a subsequent detected change. This is an inferred race, not a reproduced failure. Coordinate initial snapshots and event replay. |
| Medium | Metadata-only comparison can miss replacements or edits | Same-path content changes preserving size and modification time can leave the identity unchanged. The root directory itself is not included as a directory entry. A metadata hash is useful for reconciliation, but is not a content identity or a reliable record of writes. |
| Low | Symbolic-link assets are omitted | `project.cpp:81` skips symlink entries, including links to files within the asset root. Define a consistent supported policy across browsing, notifications, and asset-reference validation; preserve root-containment checks. |
| Medium | Watcher-to-browser behavior lacks focused acceptance coverage | `editor/tests/project_test.cpp` covers directory snapshots, source-input identity changes, cancellation, and stale generations. It does not exercise asset metadata identity plus refresh of an already-cached browser after add/delete/rename/replace. |

### Recommended notification design

Use a project-scoped filesystem notification service as the primary change trigger, with bounded asynchronous scans for initialization, reconciliation, and fallback. Treat notifications as invalidation hints and reconcile affected paths against the filesystem before publishing UI changes.

1. **Isolate platform backends.** Expose normalized create/change/remove/rename and rescan-required events through one service. Start with Linux [inotify](https://man7.org/linux/man-pages/man7/inotify.7.html); add asynchronous Windows [ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) and macOS [FSEvents](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html) behind the same interface when those editor platforms are supported. These backends have different recursion and recovery semantics; keep those differences out of panel code.
2. **Close initialization gaps.** Establish watches before publishing the initial baseline, buffer events during the scan, then reconcile/replay those events before marking the snapshot current. With inotify, install directory watches while discovering the tree and reconcile newly watched directories: a root watch alone does not cover descendants. Handle populated directories moved into the root, newly created subdirectories, and root deletion/replacement explicitly.
3. **Bound and coalesce event work.** Queue events off the UI thread with project generation and normalized root-relative paths. Use a short configurable debounce, initially around 100–250 ms, with a maximum batching delay so continuous writes cannot indefinitely postpone updates. Coalesce repeated changes by path and reconcile both parents of renames. Cap queued events, watches, concurrent jobs, and work committed per frame. Callbacks must not mutate ImGui, SDL textures, or the document.
4. **Refresh affected data only.** Invalidate listings for changed parent directories, preserve the selected asset if it still exists, and invalidate only affected thumbnails/animation descriptions. Track dependencies from textures and animation files to preview proxies; rebuild only dependent resources. Revalidate affected Inspector references and validation messages. A new unused image should refresh its folder listing without recreating Scene proxies or unrelated textures.
5. **Handle writes and atomic replacement.** Watch parent directories so replacement by rename is observed. Debounce partial writes; use write-completion information where available and bounded retry/backoff for temporarily unreadable or incomplete assets. Retain the last usable preview during transient reload failure and show an actionable status. A notified write must invalidate its cached resource even when size and modification time are unchanged. Do not automatically rewrite serialized scene references after an external rename; display unresolved references and offer an explicit repair action.
6. **Recover from lost coverage.** Kernel queue overflow, watch exhaustion, permission errors, dropped/coalesced events requiring rescan, and backend failure must mark coverage incomplete and schedule bounded reconciliation. Linux and macOS explicitly document recovery/rescan requirements in the sources above. Use bounded polling when notifications are unavailable or unreliable, including filesystems whose external changes are not reliably reported. Keep a low-frequency consistency scan and a manual Refresh action. When a global limit is reached, prioritize visible folders and referenced assets, retain the last usable state, and report incomplete coverage rather than freezing all refreshes or silently raising limits.
7. **Respect project lifecycle.** Cancel and join the old watcher on project replacement/shutdown; discard queued events and scan results from previous generations. Share the service with source/CMake tracking using separate filters and debounce rules. Keep build/run freshness validation, and never automatically overwrite a dirty open scene in response to a notification.

Recommended acceptance cases: add an image to an already-open folder; create a nested folder; move a populated directory into the root; rename/delete the selected asset; replace a texture by atomic rename; perform a same-size/same-timestamp notified write; finish a slow multi-step write; simulate startup overlap, event overflow, watch exhaustion, and a truncated fallback scan; switch projects with events pending. Verify that additions appear without another filesystem change, unrelated resources stay cached, selection is preserved where possible, and stale events cannot affect the replacement project. Use deterministic injected notification events for recovery/lifecycle tests and small real-filesystem integration cases for each supported backend. Keep diagnostic output and timing experiments within the repository's artifact budgets.

## Verification and remaining uncertainty

Reused `bin/editor-debug` and incrementally built the editor and the seven C++ editor test targets with:

```sh
cmake --build --preset editor-debug --parallel 4 --target platformator_editor platformator_editor_document_test platformator_editor_catalog_test platformator_editor_workspace_test platformator_editor_startup_test platformator_editor_preview_test platformator_editor_history_test platformator_editor_process_test
ctest --test-dir bin/editor-debug -L editor --output-on-failure --timeout 60 -j 4
```

**Result: 6/8 suites passed, 2 failed, 2.12 seconds elapsed.** CTest sets SDL dummy video/audio and software rendering for the native suites. The eighth suite tests capture-budget guards; no performance campaign was launched.

- `platformator_editor_document_test` failed at `document_test.cpp:435`: “hierarchy rows must group components under their owner while preserving saved order.” The assertion combines a hardcoded full row sequence with row-kind/parent checks. Resolve this implementation/fixture disagreement before treating hierarchy parity as verified; the failure alone does not isolate a visible hierarchy defect.
- `platformator_editor_preview_test` failed at `viewport_cases.cpp:59`: “framebuffer scale must use real x/y output ratios independently of style scale.” Inspection shows the test expects a letterboxed 360×180 logical image and 720×540 target, while `ViewportTransform::update_projection` fills the supplied 360×250 panel and calculates a 720×750 target. This is a projection-contract disagreement, not proof that framebuffer ratios are ignored. Decide and document the intended behavior, then align tests and all projection helpers. Assertions later in each failing suite were not reached.
- Process, catalog, workspace, startup, history, and capture-budget suites passed.
- Existing `editor_probe.cpp:610` timing mode measures selection plus a property command. It does not draw panels, reconcile/render the preview, load thumbnails, or run the full event loop. Its samples cannot establish GUI frame time or idle CPU usage. Historical reports were not revalidated or used to claim current performance.
- Physical GPU behavior, OS dialogs, Windows/macOS, monitor changes, scaled text/layout, keyboard-only operation, screen-reader support, and sustained interactive CPU/GPU usage remain unverified. No image dumps, source archives, or additional benchmark bundles were created.

Recommended order: restore non-sprite Scene authoring and validation feedback; resolve the failing test contracts; remove idle preview redraws and bound thumbnail memory; restore snapping/zoom/keyboard conveniences; then add search, hierarchy organization, platform backends, and larger reusable/live authoring features according to product priorities.

## Implementation follow-up (2026-11-07; status updated 2026-11-08)

The findings above remain the historical source-audit record from 2026-11-05. Subsequent implementation added targeted edit/history handling, multi-tab workspace state, bounded asset indexing and Linux filesystem notifications, recovery and diagnostics, search and transactional hierarchy moves, semantic accessibility nodes, asset-authoring tabs, and an opt-in child-process Game session. See the current story-specific records in [`specs/012-gui-cleanup/evidence`](../specs/012-gui-cleanup/evidence/) for commands and headless results; the earlier 6/8 result is not a current suite summary.

The current editor still runs only on the exercised Linux lane. A Linux install target now embeds the default layout, installs runtime libraries/resources/notices, and has passed a relocated `--help` launch; full installed GUI startup remains unverified. Detached SDL window/renderer hosts and cross-host panel movement have Linux headless coverage, while physical detached-host workflows, native Windows/macOS behavior, screen-reader use, and a matched GUI performance comparison remain unverified or incomplete. Windows UI Automation and macOS Accessibility provider sources are authored but have not been compiled or verified on their native platforms. The embedded Game view is opt-in and uses bounded frame slots; it does not forward arbitrary gameplay input. Asset notifications mark the running session stale and offer Build & Restart; the editor does not apply live asset changes. A single Hierarchy row click selects the object; deletion is routed through the Delete key or an explicit context-menu command, with headless regressions covering click/key overlap. Linux full scans are capped at 50,000 files/100,000 entries, targeted listings use smaller limits, and incomplete watcher coverage reports a degraded state. Current shortcuts, scale settings, and detached-host acceptance limits are documented in [editor/README.md](../editor/README.md). No historical timing samples or deleted binaries were reconstructed for this follow-up.
