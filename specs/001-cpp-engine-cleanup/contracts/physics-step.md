# Contract: Simulation Steps, Transforms, and Collision Events

## Canonical step

All explicit host stepping wrappers forward to one pipeline:

1. Validate finite-positive dt once; begin complete-step measurement.
2. Run eligible queued starts, then the optional existing benchmark/custom pre-step hook.
3. Run fixedUpdate; prepare affected transforms/collider desired state for physics.
4. Run broad phase, pair-local narrow phase, and serial body-support reduction.
5. Apply forces, solve contacts in deterministic order, and integrate awake dynamic/kinematic local motion.
6. Merge changed transforms, publish affected world/collider caches at their next required synchronization point, and dispatch current enter/stay/exit callbacks.
7. Run update, animation, and lateUpdate, skipping logically retired/disabled/unstarted recipients.
8. Latch/prepare the pending scene operation, reconcile structural changes, drain necessary physics/event users, dispatch readable destruction callbacks, detach/free retired ownership, and publish prepared scene registrations if replacement succeeded.
9. Finish mandatory cleanup and complete-step measurement; restore idle phase before returning or reporting a deferred error.

Geometry is synchronized before collision queries; rendering reads current synchronized world transforms. A transform changed after the current collision query affects subsequent detection rather than silently triggering another physics step. Retirements generated by callbacks cannot leave queued raw pointers into freed storage. Frame rendering is outside the simulation interval and occurs after the same cleanup boundary in every host wrapper.

`simulateFrame(dt)` performs exactly one step with the supplied dt and no event pumping/rendering/wall-time accumulator. Existing custom-callback wrappers retain their hook placement after starts and before fixedUpdate, despite their old misleading preRender parameter names. Rendering wrappers pump events, stop on quit, run the same step when eligible, then render. Benchmarks stop counting steps once the window quits.

## Interactive clock

`run` uses a steady-clock accumulator and fixed default dt of 1/120 seconds. All simulation callbacks run once per simulation step; there is no additional variable-rate update pass in this cleanup. A render iteration may execute zero to eight steps. After eight catch-up steps, drop surplus whole-step time, retain the fractional remainder, and increment an aggregate diagnostic counter. Never dump per-frame warnings in the hot loop.

Pause clears wall-time accumulation, and unpause starts from the current clock. Manual advance performs one fixed step. Explicit host/benchmark dt can differ from the interactive default, but must be recorded when comparing runs. Rendering interpolation and separate variable-rate update callbacks are out of scope.

## Hierarchy and physics ownership

Preserve additive translation-only parenting and immediate effective main-thread position reads. Parent rotation/scale/active state do not begin inheriting as a side effect of cleanup. Reparenting preserves world translation. The runtime caches hierarchy order/depth on structural edits and coalesces changed roots.

Movement workers update only their own object's local transform. They do not call a getter/setter sequence reading live ancestors. Main-thread dirty propagation updates affected descendants once per drain, including children without Rigidbodies. Pair processing/rendering uses synchronized cached transforms instead of repeated ancestry walks. A public main-thread query between edits may calculate current ancestry; repeated worker/solver paths must use the cache. Apply PR-005 if any avoidable repeated hierarchy work remains.

## Pair and support correctness

- A pair task may mutate its own manifold/support flags/result slot, but not shared Rigidbody support counts, sleep state, or scene registrations.
- Compare previous and next support flags. Reduce only nonzero transitions before support-dependent sleeping logic; pair destruction/removal also balances its support contributions.
- Use stable pair/result indexes and canonical identity keys. Deterministic active-contact membership/solver ordering must not depend on worker completion, unordered-map pointer layout, or thread-local merge order. Do not sort unchanged contact sets each frame.
- Maintain awake-dynamic, kinematic, and sleep-eligible indexes on transitions. Wake on impulse, appropriate external motion, body configuration, and last-support loss through affected work queues.
- Hold the 128-support validation layout constant when comparing worker counts; compare counts exactly and physical states with explicitly chosen tolerances.

## Enter/stay/exit semantics

A contact is an accepted narrow-phase overlap, not merely a broad-phase witness. Filtering applies bidirectionally and a trigger changes response policy without losing overlap/event bookkeeping.

- Deliver enter once on the first accepted overlap.
- Deliver stay once on each subsequent simulation step while the contact persists and the recipient is active, started, and live. This includes stationary/sleeping overlaps; it does not require recomputing unchanged geometry.
- Keep an indexed subscribed-contact list for pairs with eligible script recipients, so unchanged unobserved contacts do not incur stay-dispatch traversal merely for callbacks nobody receives. Update subscription when scripts/behaviors/activation change using affected adjacency.
- Deliver exit once when separation, filter change, deactivation, component removal, or destruction ends an accepted contact. Destroyed/inactive recipients do not receive ordinary collision callbacks; eligible survivors do.
- Exit delivery occurs before the retired other collider's allocation is freed. The legacy `other` pointer is borrowed for that callback only; retaining it requires a handle, which may already represent logical retirement.
- When enter/stay dispatch to one participant retires another participant, the latter's queued ordinary callback is suppressed. Dispatch vectors remain stable through the current phase.
- Local filter reinsertion combines witness deltas, so changing a filter that still permits the pair does not manufacture exit/enter. Off/on before a boundary coalesces to final membership.

## Geometry and numeric boundaries

Circle/box uses the closest point in box-local coordinates, an exact radius-distance test, deterministic containment/face ties, correctly oriented normal using collider centers (including offsets), penetration, and stable feature IDs. Box/box SAT uses fixed-size axes; circle/circle uses its exact center/radius geometry. Do not allocate a normal vector per tested pair.

Validate supported finite positive shape dimensions, supported scale policy, nonnegative friction/mass and bounded restitution/configuration at setters/load boundaries. Preserve intentional zero inverse mass for static/kinematic behavior; reject invalid dynamic configurations rather than producing divide-by-zero contacts. The exact scale policy is positive finite scale in this cleanup; sprite flipping uses the existing flip mode rather than negative collision dimensions. Save/load tests document any previously accepted invalid input now rejected.

Sleeping tests retain their physical intent and tolerances. If correct support accounting does not restore stack stability, investigate solver ordering, support persistence, and wake thresholds; do not reduce the scenario or widen assertions merely to obtain green results.
