# US1: frame, lifecycle and transform audit

Before source: bin/runtime-cleanup-validation/baseline-source-v2/src/gamemanager.cpp. Final source: [GameManager](../../src/gamemanager.cpp) and [declarations](../../src/gamemanager.h).

- **J1**: Runtime's ordinary rendered call reaches `simulateAndRenderFrameWithCustomCallback` with an empty callback. One body pumps events, checks quit, selects simulation, then renders. `runSimulationStepWithCustomCallback` still lists phases in order; each stage restores the prior phase. Catching the first stage error leaves transient/commit cleanup running before rethrow. Benchmarks still end the complete step before rendering. This removes a duplicated maintained control path without a new framework or allocation.
- **J2**: Object/component setters queue reconciliation; `reconcilePending` drains and allows requeueing, flushes transforms/support/collision events, then `drainRetirements` delivers destruction before freeing batches. The pointer removal path remains; unused name-removal and deletion-forwarding methods are gone. The public collection consumer now receives const through the internal accessor as well. Eligibility and system registration remain separate because callbacks can stop before physical membership catches up.
- **J3**: Dirty transforms keep one repaired queue slot per object. A hierarchy change rebuilds parent-first order; only needed queues sort. The pass stamp prevents a queued descendant from republishing after its ancestor already visited it. Workers still mutate local state, then main-thread publication refreshes colliders/wakes affected bodies. No global scan replaces this incremental path.
