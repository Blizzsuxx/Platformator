# Phase 7 convergence results

`platformator_membership_exception_test` reproduced the original failed-insertion index bug and now passes for mutable body-style and const pair-style memberships, including retry/removal. Existing bookkeeping, contact and multicell pair tests pass at one and six workers.

`platformator_asset_alias_exception_test` sweeps one-shot allocation failures across reverse entry, vector, forward map and resource publication. It checks that failed new publication leaves no cached resource or alias, that an existing resource and alias survive failures, and that retries work. It runs the publication sweep against actual texture, audio and animation wrapper types as well as a lifetime-counting resource. A capacity test grows both tables to 541 buckets, removes 299 of 300 aliases, and observes 31 buckets in each table while the last alias remains valid; it also forces one reclamation allocation failure and checks that removal continues and later reuse succeeds.

`platformator_asset_runtime_exception_test` injects failures into allocations matching long asset request strings in real texture, audio and animation loads, verifies retries and existing-resource preservation, directly sweeps failed animation-clip publication while checking release of its nested texture, and injects during staged scene preparation while ensuring an existing scene remains intact. It reports three injected failures for each new asset kind, three for each retained-resource case, and five for staged preparation. This targeted injection deliberately does not cover every unrelated allocation in the JSON library.

An opt-in broader experiment (`PLATFORMATOR_TEST_ALL_ALLOCATIONS=1`) terminates under a bad allocation in the bundled nlohmann JSON destruction path during animation loading; an instrumented stack inspection identified `basic_json::json_value::destroy`. Its heap-allocated flattening stack is in `vendored/json/json.hpp`, outside this feature's alias-publication code. The targeted tests above pass but do not establish recovery from every possible allocation failure in that third-party JSON path. `006-broad-allocation-failure.log` in `diagnostics.tar.xzdata` records the abort; core dumps were disabled.

The applicable debug and production suites each passed 26 tests with two instrumentation-only skips; the focused ASan/UBSan run passed seven tests with leak detection disabled, and the targeted TSan run passed four tests. Leak-enabled ASan again failed due to the host ptrace/LeakSanitizer limitation. Existing broader SDL audio TSan findings are not disproved by the targeted pass. Logs are retained in `diagnostics.tar.xzdata`; the ordinary suite omitted package smoke because the public API and packaging did not change in this convergence pass.
