# Phase 7 convergence results

`platformator_membership_exception_test` reproduced the original failed-insertion index bug and now passes for mutable body-style and const pair-style memberships, including retry/removal. Existing bookkeeping, contact and multicell pair tests pass at one and six workers.

`platformator_asset_alias_exception_test` sweeps one-shot allocation failures across reverse entry, vector, forward map and resource publication. It checks that failed new publication leaves no cached resource or alias, that an existing resource and alias survive failures, and that retries work. It runs the publication sweep against actual texture, audio and animation wrapper types as well as a lifetime-counting resource. A capacity test grows both tables to 541 buckets, removes 299 of 300 aliases, and observes 31 buckets in each table while the last alias remains valid; it also forces one reclamation allocation failure and checks that removal continues and later reuse succeeds.

`platformator_asset_runtime_exception_test` injects failures into allocations matching long asset request strings in real texture, audio and animation loads, verifies retries and existing-resource preservation, directly sweeps failed animation-clip publication while checking release of its nested texture, and injects during staged scene preparation while ensuring an existing scene remains intact. It reports three injected failures for each new asset kind, three for each retained-resource case, and five for staged preparation. This targeted injection deliberately does not cover every unrelated allocation in the JSON library.

An opt-in broader experiment (`PLATFORMATOR_TEST_ALL_ALLOCATIONS=1`) terminates under a bad allocation in the bundled nlohmann JSON destruction path during animation loading; an instrumented stack inspection identified `basic_json::json_value::destroy`. Its heap-allocated flattening stack is in `vendored/json/json.hpp`, outside this feature's alias-publication code. The targeted tests above pass but do not establish recovery from every possible allocation failure in that third-party JSON path. `006-broad-allocation-failure.log` in `diagnostics.tar.xzdata` records the abort; core dumps were disabled.

The applicable debug and production suites each passed 26 tests with two instrumentation-only skips; the focused ASan/UBSan run passed seven tests with leak detection disabled, and the targeted TSan run passed four tests. Leak-enabled ASan again failed due to the host ptrace/LeakSanitizer limitation. Existing broader SDL audio TSan findings are not disproved by the targeted pass. Logs are retained in `diagnostics.tar.xzdata`; the ordinary suite omitted package smoke because the public API and packaging did not change in this convergence pass.

## Phase 8: allocation failures and path diagnostics

The user replaced the bundled JSON header with an upstream development single-header version that uses allocation-free destruction. Its version macros still say 3.12.0 and its exact upstream commit is not recorded. The original limited broad sweep passed, but sweeping every measured allocation revealed a null dereference in `json_value::destroy_bounded` after a parse allocation failed. ASan/UBSan traced this through JSON parsing during animation loading. A local dependency patch treats partially initialized null array/object children as empty and avoids descending into them. Keep this patch in mind when replacing the vendored header; the version number alone does not identify the code or prove a future update contains the fix.

With core dumps disabled, the exhaustive debug run swept 45 texture, 45 audio, 120 animation and 239 scene-preparation allocation points, injecting 42, 42, 117 and 236 failures respectively. Every iteration retries; discarded scene preparation also verifies nested texture release, and a 512-level JSON value is destroyed with allocation failure armed. The full sweep passed with ASan/UBSan and leak detection disabled (118 animation and 235 scene allocation points in that build). Malformed-asset diagnostics remain covered by the asset-root test. ASan/UBSan also passed asset-root, runtime allocation, one/six-worker bookkeeping, pair cleanup, runtime recreation and scene-transition tests. Leak detection was not reverified; the prior host restriction and broader TSan/visual limitations still apply.

T047 wraps filesystem exceptions during canonicalization and file-status inspection with the exact original request and underlying error. A symlink loop tests backslash spelling for texture, audio, animation and scene loading, including preservation of the committed scene; existing traversal and symlink containment tests still pass. The rebuilt debug selection passed 25 tests, with one instrumentation-only skip; package smoke and benchmark tests were excluded from this selection. Seven focused asset, scene and lifecycle tests also passed. The debug sweep, sanitizer sweep and debug selection logs are retained alongside this file.

## Phase 9: asset reference ownership

T048 retains the incoming resource before copying its path, releases the provisional reference on failure, and commits the pointer only after preparation succeeds. Copy assignment now constructs a temporary first, and `setFilePath` prepares its replacement before releasing the current resource. The existing same-pointer and empty/unset cases remain supported. Failure-injection tests cover long canonical paths for texture, audio and animation; failed construction, set, copy construction and assignment, path replacement, runtime and staged resolver retries, preservation of another owner and eviction after failed adoption. The focused test passes in debug, with the all-allocation sweep enabled, and under ASan/UBSan with leak detection disabled. The rebuilt debug selection passed 25 tests with one instrumentation-only skip; package and benchmark tests were excluded. The existing host restriction on leak-enabled validation remains.
