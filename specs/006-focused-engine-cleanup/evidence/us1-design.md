# Asset request aliases

`GameManager` owns separate exact-request maps by resource type and reverse lists keyed by canonical path. Successful requests publish an alias only after validation and canonical cache association; exact hits use the canonical resource cache without resolving filesystem paths. Different raw spellings are first-time validated separately. Removal erases every reverse-listed alias before the resource is erased; clear operations empty aliases first. Alias memory is proportional to the raw request strings associated with cached resources; normal lookups are expected constant-time and eviction work is proportional to aliases for the evicted resource. Resources are not retained by the alias maps. This remains subject to integration and exception-path validation.
