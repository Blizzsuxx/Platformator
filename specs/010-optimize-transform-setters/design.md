# Design and behavior notes

Public position reads use an immediately maintained world translation. A main-thread position or hierarchy edit recomputes its affected subtree, so reads are constant time while an edit costs O(size of subtree). This trades extra storage and potentially repeated subtree work for inexpensive repeated reads; highly dynamic deep hierarchies can regress. Rendering and physics retain their separately synchronized snapshot. The exploratory pilot shows strong targeted gains and small possible step costs; it does not establish an overall runtime speedup.

Movement integration remains parallel over bodies and writes only each body's local state. After workers join, the main thread queues movement without refreshing the immediate values one object at a time; the already-required parent-first transform synchronization refreshes both snapshots before collision processing or callbacks. Ordinary public edits refresh immediately. A lazy cache was rejected because parallel collision readers would otherwise race while filling it. Repeated public edits to ancestors still revisit descendants; batching those edits would require a different immediate-read contract or a more complex invalidation scheme.

Same-value shape and offset assignments skip geometry and inertia work. Same-value mass, friction, restitution and gravity assignments do not wake or queue a body. Velocity and angular velocity still perform their wake checks before skipping an unchanged assignment; force and torque retain their existing wake behavior. Assigning a body type remains an explicit reinitialization even if unchanged: it clears force and torque for non-dynamic types, clears velocity for static bodies, and preserves the existing wake and response invalidation behavior. Explicit sleep and wake calls retain their prior semantics. Validation precedes equality checks.

## Implementation decision and evidence status

Retain the current implementation as a provisional candidate. Targeted correctness checks pass. The bounded pilot shows 83–98% lower medians for 100,000 deep reads, 72% lower time for the tested ancestor-edit/read mix, and 69–90% lower time for unchanged setter loops. The host-call composite of unchanged motion setters followed by a complete step was 11–14% faster in its medians; the setters ran before the runtime step. Flat reads were effectively unchanged.

The plain complete-step medians were 2–6% slower, and physics integration/movement medians were 7–8% slower. Those scopes lasted only a few microseconds and showed run-to-run variation; the larger six-worker p95 differences remain a possible regression. The synchronized immediate-position publication follows the physics-only timer and cannot directly explain the measured time in that interval. Changed queuing and object layout are possible factors within the measured path, but the captured data does not isolate their effects. The physics-scope cause and overall runtime effect remain uncertain; see the per-run ranges in [RESULTS.md](evidence/RESULTS.md). No broad game-speedup or worker-scaling claim is made.

The first capture stopped before its first sample because the capture tool initially failed to normalize typed CMake cache keys. The parser was corrected, the user later explicitly requested implementation of the converged tasks, and the bounded capture then completed once. It retained compact raw timing samples in [pilot.raw.json](evidence/pilot.raw.json). The pilot uses only three repetitions and a small body fixture without colliders or rendering; detailed collision churn, spatial skew, large live scene distributions, and broad tail behavior remain unmeasured.

The eager subtree walk is the deliberate immediate-read path and remains O(size of subtree) for each public ancestor edit; its `EFFICIENCY:` comment identifies the cost and a concrete batched-publication replacement if broader edit-heavy results warrant it. A lazy reader-populated cache remains unsuitable because concurrent readers could race while filling it.
