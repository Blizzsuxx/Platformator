# Contract: Desktop Platforms, Native Hosts, and Installation

**Requirements**: FR-031–040, FR-049–052. Support is claimed only after the specified platform evidence exists.

## Build and distribution boundary

Supported acceptance lanes are Ubuntu 24.04 x86_64/GCC 13+ on X11 and Wayland, Windows 11 x64/MSVC 2022 v143 + Windows SDK, and macOS 14 arm64/Xcode 15+ AppleClang 15+. Use CMake 3.28+ and Ninja for the supported editor workflows. Do not generalize a passing lane to all OS releases/architectures. Root runtime-only minimums remain unchanged unless a concrete dependency requires an explicit compatibility change.

CMake conditionally compiles native process/file/watch/IPC/accessibility sources. `process_internal.h` must no longer expose POSIX-only types to Windows compilation. Editor build remains optional/default OFF and ImGui/native accessibility dependencies do not enter the exported engine link interface. Linux AT-SPI uses editor-only system libdbus-1; document its development/runtime prerequisite and verify clean installed resolution. On Apple editor builds, CMake must conditionally enable the OBJCXX language (the current root project enables C/CXX only); macOS native providers compile as Objective-C++ and link required system frameworks privately; Windows native provider libraries remain editor-private.

Install the editor executable and private runtime libraries/resources. Embed the default layout, resolve optional assets relative to executable/bundle/install data, and support launch from an arbitrary cwd. Windows stages required DLLs, macOS creates an `.app` with correct Resources/Frameworks and relative load paths, Linux stages a relocatable private dependency set with relative rpaths. Include component licenses/provenance. A development source-resource override cannot be required for an installed launch. Validate relocation after removing access to original build/source directories.

## Process interface

The public editor service accepts an argument vector, working directory, output mode and explicit optional private-channel handles. It produces bounded output chunks and exactly one completion record with launch/exit/signal/error status and operation generation. Stop is idempotent; no polling frame waits for a child to exit.

- Linux/macOS: owned process group with spawn actions/chdir support discovered at configure time, nonblocking close-on-exec pipes, bounded output drain, graceful termination and current two-second force-stop deadline. Close only owned handles and reap the direct child while terminating descendants in its launch-owned process group. Supported POSIX build tools/runners must remain foreground members of that group; intentional setsid/setpgid daemon escape is an unsupported target contract, not a sandbox guarantee. A target needing detached services must register explicit lifecycle/termination integration before automatic ownership is advertised. Include a daemonizing misuse fixture and report incomplete cleanup rather than claiming success for escaped processes; normal foreground compiler/runner descendant cleanup remains mandatory.
- Windows: UTF-8→wide conversion at the boundary, explicit executable path and correct Windows argument quoting, restricted inherited handle list, suspended CreateProcessW→assign Job Object→resume. Job kill-on-close controls descendants and breakaway is not enabled. If restricted parent-job rules or handle setup prevent safe Job assignment, terminate/reap the still-suspended child and fail launch without resuming it. Use compatible graceful stop only with the required console/process-group setup, otherwise the bounded Job termination fallback; never assume CTRL_BREAK delivery. Never kill by executable name or unchecked reused PID.
- End-of-stream, catalog failure, launch failure, Stop during configure/build/query, parent close and project switch cancel queued launch. Unrelated same-name processes survive. Standard output/error remain bounded user-visible logs; structured session data uses dedicated channels.

Private session IPC is local inherited handles only: nonblocking POSIX pipes and anonymous-unlinked shared memory descriptors; Windows overlapped private pipe endpoints and an unnamed file-mapping handle inherited through the explicit handle list. Transport names/handles are not logged as user output. Cancellation wakes/cancels pending native I/O before joining its dispatcher. No listening network endpoint is exposed.

## File identities and atomic saves

Use native file identity (volume/device + file ID/inode, size, write/change times and appropriate mode/attributes) behind an OS-neutral type. UI paths are UTF-8, native Windows calls are wide; normalization must preserve case and referent semantics. Handle timestamp fields correctly for Linux and macOS rather than assuming `st_mtim` on both.

Write contract: validate destination/root and expected identity → create unique same-directory temp with create-new semantics → write all bytes → flush/close → late expected-identity check → atomic create-if-absent or explicit replacement → attempt directory/metadata durability → cleanup. Preserve supported destination attributes/permissions and any required recovery copy. Windows existing replacement uses ReplaceFileW; create-if-absent must not clobber a file appearing concurrently. POSIX uses equivalent same-directory create/replace semantics.

Results distinguish `Committed`, `Conflict`, `FailedBeforeCommit`, and `CommittedWithDurabilityWarning`. A failed precommit leaves destination unchanged and document dirty. A conflict offers overwrite/Save As/cancel, never silently retries overwrite. After replacement has occurred, report that fact and any durability uncertainty honestly; do not label changed destination as an untouched failed save. A partial preference failure does not mark scene changes saved. Retain recoverable prior valid content when the platform cannot provide the intended replacement guarantees.

Expected-identity conflict protection is optimistic, with an unavoidable check-to-replace gap against an uncooperative external writer; it is not a filesystem compare-and-swap promise. Document that boundary and test injected observed conflicts/creation races. Never waive known conflicts based on a watcher cache.

## Host window lifecycle

Each host owns `SDL_Window`, `SDL_Renderer`, `ImGuiContext`, backend state, font atlas and texture replicas. One application Runtime remains main-window-owned. Explicit Detach/Dock to Main/Move to Window moves stable panel IDs; docking/tabbing remains within a host. At most eight hosts are admitted initially; excess requests show a clear limit without losing panels. Saving/restoring assigns panels to persistent HostLayoutIds, distinct from each ephemeral WindowHostGeneration/RendererGeneration. Each context has its own saved docking/settings blob with IniFilename disabled; panel transfers serialize both affected layouts on the owner thread, never a shared default imgui.ini. Closed/removed-monitor hosts safely redock into the main host. Wayland placement is best-effort and requires no global coordinate support.

The pinned SDL3 backend warns of shared cursor/gamepad/multi-context issues. Use an editor-private, narrowly attributed adaptation that gives those native resources one owner/focus arbiter, routes events by window ID, and activates the correct context before NewFrame/process/render/shutdown. Secondary renderer errors redock its panels and invalidate only its replicas. Test cross-window text, IME, clipboard, focus, keyboard shortcuts, cursor/gamepad ownership, close/reopen and device loss. Enabling `ImGuiConfigFlags_ViewportsEnable` alone is not this implementation.

## Native accessibility

Primary controls publish stable semantic roles, meaningful names/help, values/ranges, selection/expanded/enabled/error states, logical bounds and supported actions. Providers are Windows UI Automation, macOS NSAccessibility and Linux AT-SPI. Provider callbacks acquire shared/ref-counted immutable snapshots and check host generation, keeping data alive through publication/close; unregister and drain providers before destroying their contexts/windows, then reject any queued old actions. Provider actions use the same owner-thread command/draft routing as keyboard/mouse actions with generation validation. Never call scene/Runtime APIs on provider threads. Focus/reveal of a virtualized row schedules visibility and then publishes its semantic bounds.

Scope includes welcome/project setup, menus/tools, document tabs, Hierarchy, Inspector fields/reference choices, asset browser, run/validation/Console, supported asset editors, and Game controls/read-only inspector. Include non-color status cues and visible focus. Label any unsupported custom/opaque operation precisely; do not claim screen-reader parity from a keyboard-only test. Publish deltas/visible nodes and focused paths to avoid rebuilding the whole scene tree for accessibility every frame.

## Acceptance boundary

Each lane must configure/build editor and affected engine tests, stage/install/relocate, and run Unicode/space paths, native dialogs, change notifications, file failure/conflict, owned-process-grandchild cancellation, two hosts, monitor/scaling and native accessibility inspector + screen-reader walkthroughs. Test external unrelated processes and dirty documents remain intact. On Linux include both X11 and Wayland host creation/focus/redocking. Document exact OS/tool/dependency versions and absent coverage; unsupported lanes remain outstanding rather than being marked passed by a dummy driver.
