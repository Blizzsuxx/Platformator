# Research: GUI Cleanup

**Date**: 2026-11-05 · **Status**: design decisions resolved; implementation and performance/platform verification remain outstanding.

Research combined four focused agents with inspection of the existing editor/engine, the [audit](../../docs/GUI_AUDIT.md), [specification](spec.md), pinned dependency sources, and official platform documentation. No benchmarks or application tests were executed during planning. Research agents made no source edits.

## 1. Document, selection, and command ownership

**Decision**: Introduce heap-stable `DocumentTab` aggregates owned by a `DocumentManager`. Each scene tab owns its existing `DocumentWorkspace`, `EditCommandService`, `SelectionModel`, hierarchy expansion state, Scene navigation state, diagnostics, and saved token. Add `TabId` to every asynchronous/UI address: current workspace generations start at 1 independently and cannot identify a document across tabs. Asset tabs have their own lossless asset document and history, not a scene-array parser. Only the active scene has Runtime preview proxies; immutable metadata and saved view state survive tab switching. Bind history only after its owning aggregate is stable.

**Rationale**: Current `workspace.h` has a borrowed history pointer; `editorapp.cpp` has one app-global selection, preview, and viewport. Moving these into stable aggregates preserves existing semantics while avoiding a second serializer or one Runtime per tab.

**Alternatives considered**: A generic plug-in document framework adds unrelated abstraction. One live Runtime per tab violates `Runtime::activeRuntime()` and multiplies renderer resources. Replacing all authoring state with runtime objects loses unknown serialized data.

**Decision**: Add atomic batch property and move commands. Ordered/deduplicated multi-selection has a primary object/component. Group operations prevalidate all targets, commit once, retain exact missing/present values, and roll back completely on error. Suppress independently moving descendants of another selected root. Reparent stores source/destination parent/index and before/after local translation; preserve world translation under the engine's actual translation-only parenting rule. Rotation and scale remain local; do not introduce different engine transform semantics through the editor.

**Alternatives considered**: Multiple ordinary commands break one-interaction Undo and partial-failure guarantees. Whole-document snapshots recreate the performance problem. Numeric text edits use drafts/gestures, not a command per character.

## 2. Authoring geometry and invalidation

**Decision**: Build `AuthoringIndex` from `orderedObjectIds` for all object/component markers, collider/camera bounds, selection and framing. Keep sprite Runtime proxies as a separate resource-backed subset using `orderedSpriteIds`. Use small local pose/render/animation descriptors, never recursive `cachedObject` JSON. Share canonical/legacy camera interpretation with validation; conflicting forms remain errors. Adopt the spec's full-panel projection, reversible mapping, independent pixel ratios, and separately drawn camera boundary.

**Decision**: Notifications carry value categories (pose/active, sprite, collider, camera, behavior/reference, label, structure). Reconcile only required objects/dependencies. Cache a complete Scene image by document/project/view/target/resource revisions; any relevant change redraws the full affected Scene image to preserve transparency order. Overlay changes and cursor feedback can repaint without resubmitting sprites. Visible-row topology and labels refresh by revision; clip connector segments as well as row widgets. Use existing shared sprite geometry for conservative view rejection before submission; start with a linear bounds pass on dirty views, not a second general spatial tree. Record its O(N) dirty-view cost and evaluate an index only if focused offscreen measurements justify it.

**Rationale**: Existing `preview.cpp` includes descendants in every sprite's cached object and `viewport.cpp` walks sprites for all authoring overlays. Caching eliminates repeated static draw work; simple dirty-view culling preserves order and avoids speculative indexing. O(N) structure rebuilds remain deliberate on actual structural operations.

**Alternatives considered**: Per-object partial framebuffer repair is fragile with alpha/order changes. Immediate spatial-index introduction adds maintenance/ordering costs before a measured need. Parallel UI/Runtime mutation violates owner-thread semantics.

## 3. Filesystem monitoring and startup/recovery

**Decision**: One project-scoped `ProjectChangeService` provides normalized changes from Linux inotify, Windows ReadDirectoryChangesW, and macOS FSEvents, with bounded snapshots and polling fallback. Events are invalidation hints. Start monitoring before publishing discovery; buffer events during scans, replay affected paths, and only then mark coverage current. Install watches before enumerating each new/moved-in subtree. Watch root parents/re-establish coverage when roots are replaced. Invalidate both paths and parents for a rename, including unpaired renames. Never silently rewrite document references.

**Rationale**: inotify is nonrecursive, queues can overflow and filenames can be stale; Windows subtree watching excludes changes to the watched root; FSEvents coalesces and explicitly requires rescans after loss. Remote changes on network filesystems may not be reported. A first-scan fingerprint is not an event history. Primary sources: [inotify manual](https://man7.org/linux/man-pages/man7/inotify.7.html), [ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw), [FSEvents recovery guidance](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html).

**Decision**: A serialized native I/O dispatcher waits for events and publishes immutable bounded records; it performs no scanning, decoding, UI, Runtime, or document work. CPU work uses the existing oneTBB scheduler with small bounded concurrency. A blocking OS wait must not occupy a oneTBB compute worker indefinitely. The dispatcher is an I/O integration necessity, not a competing CPU worker pool. Stop/cancel and join it before project resources are released. Publish callbacks through project generation and wake the editor loop.

**Decision**: Coalesce with a 200 ms quiet interval and a 1 second maximum batching delay. Use close-write hints when available, otherwise two stable observations; a settled notification bumps content generation even with unchanged metadata. Retry incomplete reloads with bounded backoff for at most 30 seconds, retaining last-good content; then expose Failed/Retry. Run a bounded 60-second consistency sweep, with 2-second visible-folder/referenced-asset polling when coverage is degraded/unavailable. Retain existing 50,000-file/100,000-entry full-scan bounds, make partial coverage visible, and keep demand-driven/manual refresh available. Before Build/Run perform a fresh source/asset validation and verify no intervening source generation change. Lost coverage increments a subtree uncertainty epoch so metadata-equal resources/source identities cannot remain falsely current. Same-metadata or uncertain source changes require a one-time forced rebuild at the next explicit Build/Run, never source timestamp mutation or an automatic watcher-triggered rebuild. Source notifications bump an event revision in addition to the existing metadata identity so same-metadata writes invalidate catalogs.

**Alternatives considered**: The current 3-second/5-second whole-tree polling is simple but wastes recurring I/O and misses same-metadata writes. Pure notifications cannot recover dropped events. Rescanning and releasing every resource on every event destroys locality. Increasing limits hides incompleteness and violates bounded work.

## 4. Resource preparation, dependencies, and limits

**Decision**: A `ProjectResourceIndex` tracks normalized logical paths, canonical contained targets, content versions, reverse dependencies, and directory snapshots. Canonical target changes fan out to contained symlink aliases; broken entries remain discoverable, escaping links/cycles are rejected, and retargeting updates aliases. Include texture→animation→proxy/reference dependencies; preserve selection if its logical target still exists.

**Decision**: Prepare thumbnails and animation descriptions off the UI thread; upload/destroy SDL textures on their renderer owner thread. Preflight decoded dimensions before allocation. SDL_image's public load APIs do not offer a general dimension-only probe; the pinned PNG/JPEG stb integration has a private metadata probe. Add a narrow metadata/limited-decode bridge over the already-vendored codec code, with format-specific checked probes where needed; no competing image library. SVG initially uses icon fallback: sized output does not bound parser allocations/work. Admit a sized SVG path only after parser/allocation/work guards and rejection of external resources are enforced; unsupported preview formats never call an unbounded decoder. Formats lacking safe preflight show an icon and a reason, while the existing game asset loader remains unchanged. File-byte size alone is not a decoded-memory bound. Source references: [SDL_image load](https://wiki.libsdl.org/SDL3_image/IMG_Load), [sized SVG load](https://wiki.libsdl.org/SDL3_image/IMG_LoadSizedSVG_IO), pinned `vendored/SDL3_image-3.4.8/src/IMG_stb.c` and its vendored metadata functions.

**Decision**: Initial safety caps are explicit engineering guards, not proven optimal thresholds:

| Work/storage | Initial cap | Exhaustion behavior |
| --- | --- | --- |
| Directory watches | 4,096 | Degraded coverage and bounded demand/polling fallback |
| Coalesced events | 8,192 paths and 2 MiB path storage | Collapse to root-rescan flag; never silently drop coverage |
| Recovery work | One recursive scan per root; two queued targeted scans | Deduplicate demand and defer |
| Per-frame invalidation | 256 paths or 2 ms, whichever first | Continue next wake; preserve maximum batch age status |
| Thumbnail jobs | One decoder active; 64 pending paths | Prioritize visible demand; cancel obsolete requests |
| Decode admission | Encoded bytes ≤64 MiB; each dimension ≤8,192; pixels ≤16,777,216; ≤128 MiB total decoder working set, with decoded RGBA ≤64 MiB and scratch/input staging ≤64 MiB | Icon/error fallback before unsupported allocation; instrument codec scratch; no unbounded codec path accepted |
| Completed thumbnail results | 8 MiB | Backpressure workers; discard stale results |
| Thumbnail output/cache | ≤256×256 output; 64 MiB and 256 logical entries including retained output pixels and all renderer replicas | Owner-thread LRU eviction; protect currently submitted textures until frame completion |
| Animation description | 1 MiB and 512 frames | Explicit unsupported-size error preserving old preview |
| Console/catalog | Retain existing 1 MiB raw log / 4 MiB catalog caps | Disclose truncation/reject malformed catalog |

Active Scene texture/clip preparation follows the same worker/checked-decode boundary; initial loading may show selectable pending markers rather than synchronously loading every unique image during reconcile. Retain at most 256 MiB of authoring proxy texture versions and 64 MiB for the main Scene target initially; admit uploads by byte count, evict inactive/unpinned versions or show an explicit preview-limit marker, and preserve source dimensions/source-rectangle geometry when a lower-resolution preview is used. These budgets exclude authoring DOM/history and are explicit guards, not measured optimal values.

Resource reload must actually replace versioned contents: the engine `Runtime::loadTexture` reuses retained wrappers without statting disk. Add a narrow editor-session-aware reload transaction in the engine asset manager that stages replacements and atomically swaps affected proxy/clip bindings at an idle boundary, retaining last-good resources on failure. Normal runtime loading/caching stays unchanged; no user pointers are invalidated behind their owners. Validate aliases, retained clip-frame references, and failure unwinding.

**Alternatives considered**: Keeping full images for every tiny tile is unbounded. Moving `IMG_LoadTexture` into a worker still violates renderer affinity. Removing a retained resource directly from the cache risks dangling references. A process-wide image sandbox or new worker pool is unnecessary for these bounded local assets; unsupported decoders must fail closed for preview admission.

## 5. Detached panels and accessibility

**Decision**: Use explicit Detach / Dock to Main / Move to Window actions with editor-owned SDL host windows. Each host owns an ImGui context, SDL renderer, font atlas, intra-host docking, and renderer-local resource replicas. Application document/history state remains shared. Cross-host native tab dragging is not promised. Route events by SDL window ID and arbitrate shortcuts/cursor/gamepad/IME using the focused host. Copy the pinned SDL3 platform backend into an editor-private, attribution-preserving adaptation only where needed to fix shared global resource ownership; retain upstream files unchanged.

**Rationale**: The pinned SDL_Renderer3 backend expressly lacks renderer multi-viewport support, and the SDL3 platform backend warns that multi-context sharing is not well tested. Merely enabling viewport flags is incorrect. Explicit hosts avoid unsupported Wayland global window-position assumptions; saved bounds are best-effort there. Scene rendering stays on the main Runtime renderer; when a Scene image is needed on another host, read it back only on content change and upload a bounded replica. Cached thumbnails/Game images use retained prepared pixels. Budget Scene replica/readback staging separately (64 MiB total; calculate dimensions and render/blit into an admitted transfer target before readback, downscale to a fitting aspect-preserving image with a visible resolution indicator when necessary). Never pass an SDL_Texture to another renderer. Primary references: pinned backend headers/comments, [ImGui backend guide](https://github.com/ocornut/imgui/blob/master/docs/BACKENDS.md), [multi-viewport limitations](https://github.com/ocornut/imgui/wiki/Multi-Viewports), [SDL texture ownership](https://wiki.libsdl.org/SDL3/SDL_CreateTexture).

**Alternatives considered**: A custom full multi-viewport renderer backend is larger and still constrained on Wayland. Switching the engine/editor to a different graphics API is unrelated. Unmodified multi-context initialization ignores known backend sharing issues.

**Decision**: Enable keyboard navigation and real item labels, and add a small semantic control tree with native providers: Windows UI Automation, macOS NSAccessibility, Linux AT-SPI over libdbus-1. Native callbacks retain shared immutable semantic snapshots tagged with host incarnation and drain before native host destruction; they read those snapshots and enqueue validated UI actions; they do not mutate authoring state from foreign threads. Implement meaningful names, roles, values, selection/focus, expand/collapse and supported control actions for primary flows, with real inspector/screen-reader checks. Full arbitrary custom-widget accessibility is not assumed. The Linux system dependency is editor-only and packaged/documented; the engine export is unaffected. References: [UIA providers](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview), [NSAccessibility elements](https://developer.apple.com/documentation/appkit/nsaccessibilityelement-swift.class), [AT-SPI architecture](https://gnome.pages.gitlab.gnome.org/at-spi2-core/devel-docs/architecture.html). Dear ImGui labels/navigation alone provide no OS accessibility tree.

## 6. Platform seams, supported lanes, and distribution

**Decision**: Keep OS-neutral process/file interfaces with Linux/macOS POSIX and Windows implementations. Windows uses wide arguments with correct argument quoting, explicit inherited handle lists, suspended process creation→Job assignment→resume, and kill-on-close Job Objects; no global executable-name termination. POSIX retains owned process groups and bounded graceful/force stop for supported foreground toolchain/runner descendants. Intentional daemon escape is an unsupported target contract requiring explicit registered lifecycle integration, not a sandbox containment promise; test and disclose that boundary rather than declaring all setsid descendants stopped. Windows Job assignment failure terminates/reaps the still-suspended child without resuming it. Keep child/output cleanup nonblocking in interactive frames.

**Decision**: Move Linux `stat` timestamp assumptions and atomic writer operations behind platform file identities. Stage unique sibling temporary files, flush, check expected identity late, atomically create-if-absent/replace, then report durability/cleanup outcomes. Use Windows handle metadata and ReplaceFileW/MoveFileExW semantics with proper attributes and sharing. Conflict detection is optimistic against observed changes; do not claim atomic compare-and-swap against an uncooperative external writer. Detect/reject known conflicts, keep recovery copies where replacement guarantees are insufficient, and preserve unsaved work on failure. Sources: [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew), [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).

**Decision**: Validate conservative lanes: Ubuntu 24.04 x86_64/GCC 13+ (X11 and Wayland), Windows 11 x64/MSVC 2022 v143, macOS 14 arm64/Xcode 15+ AppleClang 15+. Use CMake 3.28+ for these CI/build lanes without gratuitously raising the engine's declared minimum. Enable CMake OBJCXX conditionally for Apple editor providers. Add editor install/bundle rules and runtime dependency staging; embed the default layout, discover optional resources relative to executable/bundle, and launch from arbitrary cwd. macOS arm64 is project-validated, not claimed vendor-certified oneTBB support. Reference pinned `vendored/oneTBB-2022.3.0/SYSTEM_REQUIREMENTS.md` and [SDL platform list](https://github.com/libsdl-org/SDL/blob/release-3.4.18/docs/README-platforms.md). These lanes are planned, not tested in this session.

## 7. Reusable assets and animation authoring

**Decision**: Use editor-only versioned `.pttemplate` JSON envelopes containing a lossless subtree and typed reference bindings. Collect known bindings from compiled behavior metadata plus explicit user declarations for opaque reference sites. Instantiation always allocates fresh object/component IDs and remaps declared internal targets; external bindings store source scene/target identity and require explicit assignment in another scene, preventing same-kind numeric ID collisions. Missing schema never causes integer guessing: request declarations for unknown behavior/component reference semantics before claiming a self-contained template. Ordinary duplicate defaults retain existing numeric targets; opt-in remapping requires adequate declared bindings. Save no prefab-variant/propagation machinery in engine scenes.

**Decision**: Component copy/reset applies supported declared fields only, excludes identity/type, preserves unrelated unknown fields, and commits one transaction. Script Reset removes supported serialized overrides where constructor defaults are intentionally unknown instead of inventing defaults. Sprite region editing writes existing scene `sourceRect` fields or the selected animation frame. Animation asset tabs preserve existing `.animset` JSON and unknown members; frame duration >0 overrides clip FPS, and zero uses `1/FPS`. No new game asset parser or general-purpose sprite asset format is required.

**Alternatives considered**: Treating every integer as an object ID corrupts unrelated data. Automatic prefab propagation is outside the agreed scope. Parsing asset documents through `parse_document` incorrectly assumes a scene-array root. A thumbnail timer is not an animation-authoring clock; use the engine duration semantics.

## 8. Game view and runtime inspection

**Decision**: Keep one Runtime per process and launch a separately owned compatible runner for play. Extend catalog schema v1 with optional validated capabilities while preserving missing-capability/external-window behavior. Add opt-in versioned private inherited command/event pipes and a two-slot shared-memory RGBA8 presentation mapping. Standard output/error remain logs. No listening network service or source inference is needed.

**Decision**: Initially negotiate a 640×360, at-most-15-Hz image stream (two slots total 1,843,200 bytes), capture only while a Game view is visible, before Present and on the child Runtime owner thread, and skip capture when no slot is free. These are safety/cost caps pending measurement, not a smoothness promise. Embedded launch forces/checks actual 640×360 child render output; external launch preserves configured dimensions. Parent uploads newest complete pixels to its own renderer(s). SDL documents readback as slow/main-thread-only: [SDL_RenderReadPixels](https://wiki.libsdl.org/SDL3/SDL_RenderReadPixels). External-window Run retains native resolution/input and remains available. Embedded v1 provides viewing/control/inspection; it does not pretend that forwarding events changes direct `SDL_GetKeyboardState` polling in arbitrary custom code (Mario uses that API). V1 requires input_forwarding=false; gameplay keyboard/mouse interaction remains in external-window mode, with any future input integration requiring a separate protocol design. The spec requires Game viewing, not arbitrary input injection.

**Decision**: Apply Pause/Resume/Step and read-only inspection only at safe owner-thread boundaries. The session option implements these clock controls independently of debug-only hotkeys, including Release sessions that advertise them. Step advances exactly `FIXED_TIME_STEP` (1/120 second today); resume resets accumulated wall-clock debt. Inspection is paged/on demand and uses runtime serial + handle generation + snapshot revision, not pointers or scene IDs alone. Do not invoke arbitrary behavior serialization every frame; offer built-in state and allowlisted on-demand getters generated by the existing with-fields registration macro, convert references to handle/identity summaries, and report unavailable fields. No current custom serializer is assumed safe. No inspection result reaches authoring history/save. Unsupported code updates mark the session stale and offer Build & Restart; do not advertise general code hot reload. Compatible asset updates use an advertised safe reload capability or explicit Restart fallback.

**Alternatives considered**: A second in-process Runtime is explicitly rejected today. Native-window embedding is OS-specific and fragile. Unbounded frame streaming and full-scene inspection add predictable bandwidth/serialization cost. Generic runtime code mutation is outside the specified scope.

## 9. Diagnostics, evidence, and delivery

**Decision**: Keep a bounded raw Console log plus indexed display rows (severity/repeats/source location), expose all retained text and truncation, and use typed tab/generation/field targets for validation navigation. Incremental validation uses affected objects/reference dependents and a latest-revision completion barrier within the spec's three seconds. Explicit Validate/Run require a current full validation boundary; old results cannot authorize launch.

**Decision**: First align the two failed fixtures to intended hierarchy/full-panel behavior, preserving independent ordering/coordinate oracles and running through previously unreached assertions. Extract an `EditorApp::tick`/frame driver used by both the application and a GUI probe. Add a thin `benchmark/capture_gui.py` driver using existing `CaptureBudget`, with baseline/candidate GUI probes, compact workload identity, and cumulative 50 MiB/600-second bounds; keep old feature-011 `capture_editor.py` modes historical. Rendering comparisons use `benchmark/capture_linear_render.py` only, inside the same remaining session budget where combined. No automatic legacy acceptance campaign or replacement failed-session directory.

**Decision**: Each experiment selects one focused interaction, idle, or affected-resource scenario for the change under test, with 3 repetitions / 5 warmups / 30 measured frames. Record idle CPU over a bounded wall interval separately; sample p95/max without overstating statistical strength. Broader correctness fixtures cover 10,000 objects, depth 128, monitor/DPI/input, and real platform providers without turning every dimension into a performance matrix. Compare one versus a small multiworker configuration only for independent decode/scan throughput when relevant; keep engine fixed-step and normal runtime regression checks separate. Retain reports, commands, workload/build/hardware/worker identities and raw timings; frames remain transient memory. New measured evidence, including absent physical platforms, stays explicitly outstanding until implementation.

**Alternatives considered**: The existing editor timing mode measures selection + a property edit only and hardcodes feature-011 sessions. It cannot establish idle/UI frame behavior. Broad historical campaigns conflict with the repository's current compact-artifact policy.

## Design review closure

Cross-artifact research review tightened per-directory request/revision checks, loss/overflow uncertainty epochs (including same-metadata changes), targeted/fallback I/O bounds, inclusive decoder working-set accounting and unsupported SVG fallback, pre-readback transfer admission, persistent HostLayoutId versus host/renderer incarnation, per-context layout blobs, ref-counted accessibility callback lifetime, explicit template external identity, generated inspection getters and live handles, fixed child capture dimensions, inherited-channel/nonblocking-write ownership, Release pause/step capability, Apple OBJCXX setup, Windows failed Job assignment cleanup, and the foreground POSIX ownership boundary. These are design decisions with implementation tests, not verified fixes. No unresolved research clarification or constitution exception remains.
