**Input.** [Specification](spec.md), [plan](plan.md), [data model](data-model.md), [runtime contract](contracts/sprite-ordering.md), [authoring contract](contracts/authoring.md), [research](research.md), and [validation guide](quickstart.md). Paths in tasks start at the repository root. All five stories are P1. US5 precedes US4 because the performance comparison needs the finished culling policies.

**Execution.** Follow the IDs in order for a single implementer. Mark a box after its stated change or check is observable. Tests added before implementation may initially fail for the specified behavior. Keep related producer/consumer edits together until the phase checkpoint passes. For example, land T007–T012 together so no intermediate build draws the unsorted candidate vector. For a named CTest target, build it with `cmake --build --preset test --parallel 4 --target TARGET` and run `ctest --test-dir build/test --output-on-failure -R "^TARGET$"`, substituting the real name. The benchmark CLI target uses the separate build in quickstart §4. A passing build alone does not verify ordering, culling work or performance.

**Three different orders matter.** A *slot* indexes the dense window registry and may move on removal. A *registration sequence* follows the surviving sprite and breaks Z ties. *Retained membership* contains the slots the current culling policy will consider for drawing, including conservative candidates. Only the final draw list is sorted by the visual key. Keep direct Camera calls caller-ordered and physics colliders independent of render visibility.
